# Pirate Cinema — handoff

Актуально на 15 сентября 2026 года.

Это основной handoff-документ проекта. При расхождениях с другими handoff-файлами следует ориентироваться на этот файл, затем на фактический код, тесты и `docs/PROJECT.md`.

## Кратко

Pirate Cinema превращён в локальное Electron-приложение для поиска, хранения и просмотра торрент-медиа. Интерфейс работает через локальный Node API, TorrServer и MPV. Библиотека, метаданные и история просмотра сохраняются локально в SQLite; облачное хранение не используется.

Последний опубликованный стабильный релиз: **0.5.7**.

- Репозиторий: <https://github.com/cyberboy1999/pirate-cinema>
- Релиз: <https://github.com/cyberboy1999/pirate-cinema/releases/tag/v0.5.7>
- Ветка: `main`

## Что было сделано

### Локальное приложение и воспроизведение

- Собрана связка Electron → React/vinext → локальный Node API → TorrServer → MPV.
- TorrServer оставлен отдельным локальным сервисом с настраиваемым адресом, по умолчанию `http://127.0.0.1:8090`.
- MPV включён в Windows-сборку; на Linux используются системные MPV и FFmpeg.
- Реализовано управление MPV через IPC: запуск, фокус окна, остановка, следующая серия и опциональное автопродолжение.
- История хранится отдельно для каждого файла торрента: позиция, длительность и признак запуска.
- Добавлены продолжение с сохранённой позиции, запуск сначала и защита от случайного открытия дубликатов.
- Сохранение прогресса выполняется примерно каждые пять секунд, а также при переключении, завершении и закрытии.
- Добавлен выбор встроенного MPV или внешнего Windows-плеера. Для внешнего плеера точная позиция не отслеживается.
- Добавлены выбор аудиодорожки, естественная сортировка сезонов/серий и переход к следующему непросмотренному файлу.

### Библиотека и метаданные

- TorrServer является источником списка сохранённых торрентов; локальная SQLite-база хранит карточки, метаданные и историю.
- Синхронизация не очищает библиотеку при ошибочном или пустом ответе TorrServer.
- Полная синхронизация обновляет метаданные всех карточек; фоновая использует суточный кэш.
- Постеры и основные метаданные ищутся через Cinemeta, описания — прежде всего через русскую Wikipedia; предусмотрены ограниченные fallback-сценарии.
- Добавление magnet-ссылки сразу извлекает чистое название и год из `dn`, создаёт карточку и запускает существующий поиск метаданных.
- Добавлен редактор названия карточки. Исправлен первоначальный вариант на `window.prompt`: теперь используется встроенное модальное окно с валидацией и выводом ошибок.
- Ручное название хранится как `metadata_query` и не теряется при последующих синхронизациях.
- При ручной коррекции очищается ошибочное сопоставление и выполняется новый поиск постера и описания.
- Год релиза повторно используется при неоднозначном поиске ремейков.

### Интерфейс

- Выбран стиль «лаконичный домашний кинотеатр»: почти чёрный фон, тёмно-серые поверхности, светлый текст и зелёный только для успеха/статуса.
- Упрощены рамки, панели, кнопки и типографика; унифицированы отступы и состояния элементов.
- Боковая панель стала уже, поиск и статус TorrServer — компактнее.
- Главная показывает одну крупную карточку «Продолжить просмотр», затем горизонтальную полку популярных фильмов.
- Домашний каталог загружает до 30 фильмов из публичного каталога Cinemeta и использует встроенный fallback.
- Для полок длиннее шести карточек добавлена прокрутка влево/вправо с доступными кнопками.
- Карточки унифицированы; убран декоративный `TOP`.
- В медиатеке добавлены фильтры по типу, просмотру, году и жанру, сортировка, поиск по сериям и выбор сезона.
- Уплотнены экран фильма, список файлов/серий и действия воспроизведения.
- Добавлены русская и английская локализации основных экранов и служебных действий.
- Electron работает через системный трей: закрытие окна скрывает приложение, выход через трей завершает принадлежащие приложению процессы.

### Диагностика, обслуживание и безопасность данных

- Добавлены проверки API, TorrServer, MPV, FFmpeg, выбранного плеера и SQLite.
- Добавлена диагностика конкретного файла перед повторным запуском.
- Реализованы резервные копии локальных данных и восстановление с явным подтверждением и перезапуском.
- Добавлено автоматическое обновление Windows через публичные GitHub Releases; установка выполняется после подтверждения/выхода.
- Первый запуск предлагает язык и плеер; настройки сохраняются локально.
- Удалены старые Cloudflare Worker, D1/Drizzle и Sites-зависимости. Проект остаётся local-first.
- MEX выведен из эксплуатации и архивирован; активной частью проекта не является.
- Ponytail используется только как локальная инструкция разработки, без runtime-зависимостей и телеметрии.

### Сборка и выпуск

- Подготовлены Windows Offline Setup и небольшой Web Setup.
- Добавлены Linux-пакеты DEB, RPM, Arch `tar.gz`, `PKGBUILD` и установочный скрипт.
- Windows-установщики запрашивают UAC только при установке/обновлении; само приложение работает без повышения прав.
- GitHub Actions собирает платформенные пакеты, проверяет хэши MPV/TorrServer и публикует единый релиз.
- В релизы добавлены `SHA256SUMS` и `THIRD_PARTY_NOTICES.md`.
- Описания релизов публикуются на русском и английском.

## Jackett / Prowlarr / Torznab

- В настройках Pirate Cinema есть опциональные поля URL и API-ключа внешнего Jackett/Prowlarr.
- Дополнительный EXE не встраивается и не запускается приложением.
- Для локального Jackett используется агрегированный endpoint:

  `http://127.0.0.1:9117/api/v2.0/indexers/all/results/torznab/`

- API-ключ хранится локально и маскируется в ответах API Pirate Cinema.
- TorrServer должен получать `CatType: all`, иначе его стандартный фильтр категорий может скрыть выдачу Jackett.
- Результаты с magnet/hash и HTTP(S)-ссылками на `.torrent` принимаются; прочие схемы отклоняются.
- Результаты маркируются как `Jackett · <название индексера>` и объединяются с RuTor с дедупликацией.

API-ключи, логины, пароли и cookie намеренно не записаны в этот handoff и не должны попадать в Git.

## Ключевые файлы

- `app/page.tsx` — главная, поиск и медиатека.
- `app/Playback.tsx` — карточка фильма, файлы и запуск просмотра.
- `app/Preferences.tsx` — настройки и диагностика.
- `server/api.mjs` — локальные API-маршруты и orchestration.
- `server/torrserver-client.mjs` — TorrServer, Torznab и нормализация результатов.
- `server/library-sync.mjs` — синхронизация и обогащение библиотеки.
- `server/database.mjs` — SQLite и история просмотра.
- `server/mpv-player.mjs` — MPV и IPC.
- `server/wikipedia.mjs` — поиск описаний Wikipedia.
- `electron/main.mjs` — жизненный цикл приложения и локальных сервисов.
- `.github/workflows/release.yml` — основной release workflow.
- `docs/PROJECT.md` — подробный актуальный технический контекст.
- `THIRD_PARTY_NOTICES.md` — лицензии и сведения о встроенных бинарниках.

## Неподлежащие изменению контракты

- Не добавлять облачное хранение и не отправлять библиотеку внешним сервисам без явного разрешения пользователя.
- Не коммитить API-ключи, cookie, базы данных, кэши, backup-файлы, бинарники и установщики.
- Не останавливать TorrServer/MPV, если процесс не был запущен самим приложением.
- Сохранять MPV IPC и раздельную SQLite-историю для каждого файла.
- Публиковать релиз только после явного разрешения пользователя.
